BiciCampus · bicis y patinetes compartidos del campus de Vera

El campus tiene 60 bicis y 20 patinetes eléctricos en 8 estaciones. A las 8:30 el Ágora está vacío y a las 14:00 la Biblioteca no tiene ni un hueco libre. El Vicerrectorado de Campus (stakeholder ficticio) quiere una plataforma que gestione el préstamo con reglas claras, cobre lo justo, atienda las averías y diga al operario dónde tiene que ir.

El contexto completo, con los usuarios de demo y el glosario, estará en la épica E0 de la wiki el día 1. No necesitáis saber más para prepararos: el entorno, Claude Code y OpenSpec son los mismos.

La aplicación de un vistazo

Tres roles

USUARIO (comunidad UPV), OPERARIO (mantenimiento) y GESTOR (panel de flota). Sin login real: un selector de usuario de demo.

Reglas con números

Batería mínima, docks libres, tarifas por tiempo, bonos, tope diario y bloqueos. Todo se puede comprobar con ejemplos concretos.

Fuera de alcance

Mapa, GPS y tiempo real. Una lista de estaciones con sus cifras basta: no gastéis crédito en ello.

Lo que ya está fijado

Sin IA en el producto

La aplicación no contiene IA. La IA es la herramienta con la que se construye.

Un mismo reto para todos

Los 8 equipos construyen la misma aplicación, para poder comparar sistemas y no productos.

Pequeña a propósito

Cuatro épicas base más una stretch y dos cambios de requisitos, en unas 6 horas netas de trabajo.

Cómo se os presentarán los requisitos

Los requisitos llegan como épicas publicadas en esta wiki (sección Épicas), que vuestros agentes descargan de internet. No hay tablero ni cuentas extra. No hay historias escritas: las escribe vuestro sistema (fase 1 del ciclo).

Cómo es una épica

Todas las épicas siguen la misma estructura, así que podéis preparar vuestro sistema para leerlas:

  • Objetivo y usuarios implicados.
  • Reglas de negocio numeradas (R1, R2…), que los coaches pueden comprobar en vivo.
  • Contrato de API y códigos de error: se usan tal cual, forman parte del criterio de funcionalidad.
  • Fuera de alcance, para que no gastéis crédito en lo que no puntúa.

Requisitos técnicos Confirmados

Esto es lo que se prevé para BiciCampus. Si algo cambia, se avisa aquí.

StackNode 22 + TypeScript + Express + SQLite + React/Vite + Vitest. Los comandos de arranque están en .claude/hints/stack-y-estandares.md.
Arranquenpm install && npm run dev, sin Docker ni servicios externos.
DatosSQLite con datos semilla cargados al arrancar (npm run seed).
APIREST y JSON. Los errores de negocio devuelven 409 o 422 con { code, message }.
InterfazEn castellano, responsive y con un mínimo de accesibilidad (etiquetas y contraste).
AutenticaciónFuera de alcance. Un selector de «usuario de demo» basta: no puntúa y gasta presupuesto.
TestabilidadTodo lo que dependa del tiempo (reservas de 10 minutos, límites de uso, tarifas) debe poder simularse, para poder probarlo.

Cómo prepararse mientras tanto

    Completad los prerrequisitos y asistid a la sesión de setup.

  2. Leed las pistas del repo.

    Los ficheros de .claude/hints/ no dependen de la aplicación.

  3. Revisad las plantillas de agentes.

    Practicad el formato en Agentes: plantillas y guía para llegar al taller con ideas.

    Hablad de quién se siente cómodo con qué: requisitos, tests, seguridad, pitch.
