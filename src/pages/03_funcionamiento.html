La idea del hackathon

Cada equipo recibe el mismo reto: una aplicación con requisitos de negocio (BiciCampus; los requisitos se publican el día 1). Pero no la programáis a mano. Vuestro trabajo es diseñar y construir un sistema de agentes con Claude Code que la construya, guiado por especificaciones (Spec-Driven Development con OpenSpec).

Lo que se evalúa

Cómo construís: el diseño de vuestro sistema de agentes, las specs, los guardarraíles, la adaptación al cambio y el coste.

Lo que importa menos

Cuánta aplicación tenéis. El producto pesa un 15 % y no puede contener IA: la IA es vuestra herramienta, no una funcionalidad.

Objetivos de aprendizaje

Spec-Driven Development

La especificación manda y la IA implementa. Aprenderéis a proponer, aplicar y archivar cambios con OpenSpec y a mantener la trazabilidad de la épica al test.

Vuestro sistema de agentes

Diseñar agentes con roles, contratos de entrada y salida, memoria y puertas humanas, y descubrir cuándo un sistema de agentes merece la pena.

Claude Code a fondo

Subagentes, skills, comandos, hooks, permisos y gestión del contexto, con crédito de API para practicar de verdad.

El ciclo que vuestro sistema debe automatizar

Hay cinco fases. Vuestro sistema tiene que agentizar las cinco; podéis añadir más, pero cerrar el ciclo completo de al menos una épica vale más que muchas fases a medias.

#FaseEntraSale (mínimo esperado)
1RequisitosÉpicas (wiki del evento)Historias de usuario como issues, con criterios de aceptación en Gherkin y enlazadas a su épica
2PlanificaciónHistoriasPrioridad, estimación, dependencias y reparto
3ImplementaciónHistoria + spec OpenSpecUn change OpenSpec por historia o grupo de historias, y el código
4Calidad y seguridadCódigo + spec + criteriosTests que trazan a los criterios, npm test en verde e informe de seguridad
5EntregaTodo lo anteriorDocumentación, notas de versión y docs/evidencias/

Entre fases hay puertas humanas: puntos donde una persona del equipo aprueba antes de seguir (historias, spec, veredicto de QA). Un agente nunca se aprueba a sí mismo.

Qué se espera de vuestro equipo

Un sistema de agentes

En .claude/: agentes, skills y comandos propios, más un CLAUDE.md. Cada persona diseña al menos una pieza.

Specs vivas

En openspec/. Si el código se desvía, se corrige primero la spec. Los changes terminan archivados.

Una app en main

Funcionando, con tests y CI en verde. Se reproduce con npm install && npm run dev.

Evidencias

En docs/evidencias/: arquitectura, trazabilidad, cambios, coste y lecciones.

Trabajo de equipo

Todos aparecen en el git log y todos responden en el turno de preguntas.

Un pitch de 5 minutos

Con una demo del sistema de agentes trabajando, no solo de la app.

Tres ideas que lo cambian todo

  1. El sistema de agentes es lo que se evalúa.

    La aplicación es la excusa para ponerlo a prueba.

  2. La spec manda.

    Si el código y la spec no coinciden, se corrige la spec y luego el código. Cuando lleguen cambios de requisitos, se abre un change nuevo; no se parchea el código.

  3. Pequeño y completo gana a grande y a medias.

    En la edición anterior, equipos con 9–14 agentes cerraron una épica de trece. Entre 4 y 6 agentes que cierran el ciclo suelen ser mejor sistema.

Presupuesto y modelos

Cada persona tiene ~50 $ de crédito de API (≈ 200–250 $ por equipo), que se reclama el día 1 (cómo hacerlo). Cuando se acaba, se acaba. La statusline de Claude Code muestra el gasto: 🟢 por debajo del 70 %, 🟠 entre el 70 y el 90 % y 🔴 a partir del 90 %.

ModeloÚsalo para
haikuTareas mecánicas: clasificar, formatear, mover datos a issues, resúmenes, lint de specs.
sonnet (por defecto)Requisitos, specs, código y tests: el caballo de batalla.
opusSolo decisiones difíciles (arquitectura del sistema, revisión de seguridad final), y justificado en docs/evidencias/.

Elegir bien el modelo para cada agente puntúa en el criterio de eficiencia. Consejos para gastar menos: /clear entre tareas distintas, pasar a los agentes rutas de fichero y no copias de contenido, poner tope de 2–3 vueltas a cualquier bucle de corrección y ejecutar los tests solo del fichero afectado.

Qué os lleváis

  • Un método (SDD) para trabajar con IA sin perder el control de lo que se construye.
  • Un sistema de agentes propio, reutilizable en vuestros proyectos, en vuestro repo.
  • Criterio para decidir qué automatizar, qué no y dónde poner a una persona.
  • Experiencia real de coste: cuánto cuesta una historia y qué lo encarece.
  • Práctica de trabajo en equipo con cambios de requisitos y presión de tiempo, y de contar el resultado en un pitch.

Antes del día 1

Haced esto antes de la sesión online de setup. Os llegará por correo antes del 23 de noviembre.

  1. Portátil y sistema.

    macOS, Linux o Windows 10/11. En Windows, instalad también Git for Windows.

  2. Node.js 22 LTS, Git y GitHub CLI (gh).

    Comprobad con node -v, git --version y gh --version.

  3. Cuenta de Claude Console (gratuita).

    Entrad en platform.claude.com, iniciad sesión o crear una cuenta con vuestro correo. Hacedlo antes del día 1 para que nadie espere al empezar: el crédito se reclama allí (ver Tu crédito de API).

  4. Claude Code.

    Con el instalador nativo (code.claude.com/docs). Al lanzar claude por primera vez, iniciad sesión con vuestra cuenta de Console (uso con crédito de API), no con una suscripción de Claude.ai.

  5. OpenSpec CLI.

    npm install -g @fission-ai/openspec@latest

  6. Cuenta de GitHub.

    La necesitamos en la inscripción para daros acceso al repo de equipo. Ejecutad gh auth login.

  7. Clonad el repo del equipo y ejecutad /setup.

    Abrid claude en la raíz del repo y repetid /setup hasta ver LISTO. Una sola persona del equipo ejecuta openspec init (eligiendo Claude Code), hace commit y push; el resto, git pull.

  8. Leed .claude/hints/00-empieza-aqui.md.

    Son 10 minutos y contienen las reglas del juego.

Tu crédito de API

Anthropic aporta 50 $ de crédito de API por participante. Se reclama el día 1, al empezar el evento, con un enlace que os enviaremos por correo ese mismo día. No hay que hacer nada con el crédito antes, salvo tener lista la cuenta de Console.

  1. Antes del día 1: tened la cuenta de Console.

    Iniciad sesión o crear una cuenta gratuita en platform.claude.com. Usad el correo con el que vais a trabajar en el evento.

  2. Día 1: abrid el correo con el enlace de crédito.

    Llega al empezar. Iniciad sesión en platform.claude.com y reclamad el crédito desde el enlace.

  3. Esperad un minuto.

    El crédito aparece en vuestra cuenta en aproximadamente un minuto. Después podéis iniciar sesión en Claude Code con esa misma cuenta.

Es crédito de API, no una suscripción

Va a vuestra organización de Console. No es Claude.ai Pro ni Max: el chat de claude.ai no lo usa; sí lo usan Claude Code y la API.

Caduca a los 90 días

Contados desde el día en que lo reclamáis. Por eso el enlace se comparte el día 1 y no antes.

El enlace es solo para participantes. No está protegido con contraseña y el cupo total es limitado y por orden de llegada: si el enlace sale del evento, el crédito puede acabar en manos de quien no participa. No lo compartáis ni lo publiquéis.
